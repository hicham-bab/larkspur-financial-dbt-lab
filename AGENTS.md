# Instructions for coding and analytics agents

This repo is a dbt Mesh of four projects (`platform`, `finance`, `marketing`,
`data_science`) over the Fivetran Financial Services source. The platform is a Data Vault
2.0 built with datavault4dbt: `01_staging` (hashing), `02_raw_vault` (hubs, links,
satellites), `03_intermediate` (business rules), `04_marts` (gold), `05_semantic_layer`.

- Before answering a data question, read `context/agent_instructions.md`. Before
  changing a model, read `context/data_caveats.md`: every caveat there is guarded by a
  test in `platform/tests/`.
- Governed numbers come from the Semantic Layer metrics in
  `platform/models/04_marts/core/*.yml` and `platform/models/05_semantic_layer/metrics.yml`,
  plus each consumer's own metrics (`finance`, `marketing`). Do not redefine them in SQL.
- Raw vault and staging models are generated by datavault4dbt macros: before adding or
  changing one, read the skills in `platform/.agents/skills/` (using-datavault4dbt first).
  Keep cleaning out of the vault; business rules belong in `03_intermediate`.
- dbt conventions: Fusion-conformant (no `config-version`, `cast()` not `::`,
  `arguments:` on generic tests). Public platform marts have enforced contracts:
  update the YAML `data_type` when you change a column.
- Never select the loan source's identity columns (`ssn`, `social_security_number`,
  `ssnumber`, `ssnumber1`, `dl`, `drivers_license`) or return names or emails.
- After changing models or metrics, regenerate the Fivetran Context Layer load script
  with `context_layer/publish_context_layer.py`.
